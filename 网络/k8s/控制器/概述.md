# 🧭 Kubernetes 控制器（Controller）笔记

控制器是 Kubernetes 的核心组件之一，用于自动管理集群中的 Pod 与其他资源对象。它们通过**控制循环（Control Loop）**不断地检测实际状态是否与期望状态一致，并自动执行修复或更新操作。

---

## 🌐 1. 概述（Overview）

Kubernetes 控制器负责：

* **监控资源对象**的状态（如 Pod、ReplicaSet 等）；
* **比较实际状态与期望状态**；
* **执行操作**（如创建、删除、重启 Pod），以使系统回到期望状态。

常见的控制器包括：

* Deployment
* StatefulSet
* DaemonSet
* Job / CronJob
* ReplicaSet / ReplicationController
* HPA（Horizontal Pod Autoscaler）
* Ingress 控制器
* 准入控制器（Admission Controller）

---

## 🚀 2. Deployment

**用途**：用于管理无状态应用的部署与滚动更新。

**特点：**

* 管理 ReplicaSet；
* 支持滚动升级（Rolling Update）和回滚（Rollback）；
* 适用于无状态服务（如 Web 服务、API 服务等）。

**示例：**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
```

**常用命令：**

```bash
kubectl rollout status deployment/nginx-deployment
kubectl rollout undo deployment/nginx-deployment
kubectl scale deployment/nginx-deployment --replicas=5
```

---

## 🧱 3. StatefulSet

**用途**：管理**有状态应用**（如数据库、ZooKeeper、Redis Cluster 等）。

**特点：**

* Pod 拥有**稳定的身份标识（DNS 名称）**；
* Pod 拥有**稳定的持久化存储（PVC）**；
* 按顺序部署与删除；
* 支持滚动更新，但更新顺序严格控制。

**典型应用场景：**

* MySQL 主从集群
* Kafka / RabbitMQ
* Elasticsearch 集群

---

## ⚙️ 4. DaemonSet

**用途**：确保每个（或部分）节点上都运行一个特定 Pod。

**特点：**

* 每个节点上部署一个副本；
* 常用于**系统级守护进程**；
* 新节点加入集群时自动部署 Pod。

**典型场景：**

* 日志收集（Fluentd / Filebeat）
* 节点监控（Prometheus Node Exporter）
* 网络插件（CNI）

---

## 🔁 5. ReplicationController 和 ReplicaSet

**ReplicationController (RC)**：

* Kubernetes 早期版本的副本控制器；
* 保证指定数量的 Pod 副本处于运行状态。

**ReplicaSet (RS)**：

* RC 的升级版本；
* 支持 **Label Selector** 的高级匹配；
* 一般由 Deployment 自动创建和管理。

---

## 🧩 6. Job

**用途**：用于执行一次性任务（One-time task）。

**特点：**

* Pod 运行完成后自动退出；
* 可配置并行执行多个任务；
* 常用于批处理、数据迁移等。

**示例：**

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: data-import
spec:
  template:
    spec:
      containers:
      - name: importer
        image: busybox
        command: ["echo", "Data imported"]
      restartPolicy: Never
```

---

## ⏰ 7. CronJob

**用途**：定时执行任务（如 Linux 的 cron）。

**特点：**

* 基于时间调度；
* 自动创建 Job；
* 可配置并发策略与历史记录保留数量。

**示例：**

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-job
spec:
  schedule: "0 3 * * *" # 每天凌晨3点
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: busybox
            command: ["sh", "-c", "echo Backup done"]
          restartPolicy: OnFailure
```

---

## 🌉 8. Ingress 控制器

**用途**：负责 HTTP/HTTPS 路由转发，是集群的“入口网关”。

**功能：**

* 基于主机名或路径的路由；
* 负载均衡；
* TLS 终止；
* 支持反向代理与重定向。

**常见实现：**

* Nginx Ingress Controller
* Traefik
* Istio Gateway

---

## 📈 9. HPA（Horizontal Pod Autoscaler）

**用途**：根据指标（如 CPU、内存、自定义指标）自动水平扩缩容。

**特点：**

* 动态调整 Pod 副本数；
* 支持自定义指标（通过 Metrics API）；
* 与 Deployment / ReplicaSet 搭配使用。

**示例：**

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: nginx-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx-deployment
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 60
```

---

## 🛡️ 10. 准入控制器（Admission Controller）

**用途**：拦截请求（创建/修改等）并进行验证或修改。

**分类：**

* **MutatingAdmissionWebhook**：可修改对象；
* **ValidatingAdmissionWebhook**：仅验证；
* 可用于安全策略、命名规范、资源配额控制等。

**典型用途：**

* 限制命名空间内的资源；
* 自动注入 Sidecar；
* 验证资源标签或镜像来源。

## 🧭 总结对比表

| 控制器         | 功能      | 适用场景       | 是否有状态 | 是否持续运行 |
| ----------- | ------- | ---------- | ----- | ------ |
| Deployment  | 无状态应用   | Web 服务、API | 否     | 是      |
| StatefulSet | 有状态应用   | 数据库、消息队列   | 是     | 是      |
| DaemonSet   | 节点守护进程  | 监控、日志收集    | 否     | 是      |
| Job         | 一次性任务   | 批处理、数据导入   | 否     | 否      |
| CronJob     | 定时任务    | 备份、报告生成    | 否     | 否      |
| HPA         | 自动扩缩容   | 动态负载       | 否     | 是      |
| Ingress 控制器 | 流量入口管理  | Web 路由     | 否     | 是      |
| 准入控制器       | 请求验证与修改 | 安全与合规      | 否     | 是      |
