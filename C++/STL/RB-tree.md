### 红黑树（Red-Black Tree）深度解析

[红黑树（图解+秒懂+史上最全） - 技术自由圈 - 博客园](https://www.cnblogs.com/crazymakercircle/p/16320430.html)

红黑树是一种自平衡的二叉搜索树，它具有特定的规则来保持树的平衡性，从而保证插入、删除和查找操作的最坏时间复杂度为 **O(log n)**。红黑树被广泛应用于许多高效的数据结构和算法中，例如 C++ STL 中的 `set` 和 `map`，Java 中的 `TreeMap` 和 `TreeSet` 等。

### 一、红黑树的结构与基本规则

红黑树具有以下特性，这些特性是确保它能自平衡的核心：

1. **节点颜色**：每个节点都有一个颜色，红色或黑色。
2. **根节点是黑色的**：红黑树的根节点必须是黑色。
3. **叶节点是黑色的**：红黑树的所有叶节点（即 `NIL` 节点，表示空节点）都是黑色的。
4. **红色节点的子节点必须是黑色的**：红色节点的两个子节点都必须是黑色的，也就是说，不能有两个连续的红色节点出现在树的任何路径上。
5. **每个路径上的黑色节点数量相同**：从任意节点到其所有叶子节点的路径上，必须包含相同数量的黑色节点，这个数量称为黑色高度。

#### 颜色的作用

红黑树引入的“红色”和“黑色”节点颜色，实际上帮助控制树的高度。当插入新节点时，我们保持大致的平衡，防止树在最坏情况下变成线性结构（即退化成链表）。通过这些规则，红黑树保持了相对较低的高度，从而在进行查找、插入和删除操作时能够保证对数时间复杂度。

#### 规则总结

* **根节点是黑色的**：根节点是黑色，避免了根节点为红色时可能引发的双红问题。
* **红色节点的子节点是黑色的**：不允许两个红色节点相邻，这防止了树的高度过高。
* **叶子节点是黑色的**：每个叶子节点（`NIL`节点）都是黑色，保证了黑色节点的数量一致性。
* **黑色节点数量一致性**：从根到每个叶子的路径中，必须有相同数量的黑色节点，这保证了红黑树的相对平衡性。

通过这些规则，红黑树的高度始终是对数级别的（即 **O(log n)**），从而确保了树操作的效率。

### 二、红黑树的操作

#### 1. **插入操作**

红黑树的插入操作通常包括以下步骤：

1. **普通插入**：在普通的二叉搜索树中，找到合适的位置并插入新节点。新插入的节点默认为红色。
2. **修复违反规则的性质**：插入后可能违反了红黑树的某些规则，特别是双红冲突（父节点和插入节点都为红色）。为了解决这些冲突，我们需要进行修复。

插入修复的过程可以分为三种主要情况：

* **Case 1：父节点和叔叔节点都为红色**：此时我们通过颜色调整将父节点和叔叔节点都染黑，将祖父节点染红，然后递归地修复祖父节点的问题，直到根节点或没有违反规则为止。

* **Case 2 & Case 3：父节点为红色，叔叔节点为黑色**：这时我们根据插入节点与父节点、祖父节点的相对位置进行旋转修复：

  * **Case 2**：如果插入节点与父节点不在同一方向（例如父节点是祖父节点的左子节点，而新节点是父节点的右子节点），需要先对父节点进行左旋，再进行右旋。
  * **Case 3**：如果插入节点与父节点在同一方向（例如父节点是祖父节点的左子节点，而新节点是父节点的左子节点），则直接对祖父节点进行右旋。

**旋转操作**是保持树平衡的关键。旋转的目的是通过调整节点的位置来改变树的结构，从而保持红黑树的性质。

#### 2. **删除操作**

删除节点的操作更为复杂，删除可能导致树的不平衡，特别是删除黑色节点时。为了保持红黑树的性质，删除后需要进行 **删除修复（Delete Fixup）**。

删除操作的步骤如下：

1. **查找并删除节点**：删除节点时，找到该节点的位置。如果该节点有两个子节点，则用后继节点（或前驱节点）代替该节点。
2. **修复不平衡**：删除节点后，可能破坏了黑色节点的数量一致性（导致“双重黑色”）。通过旋转和重新着色来恢复树的平衡。

#### 3. **查找操作**

查找操作与普通的二叉搜索树查找一样，基于键值的比较进行。由于红黑树是自平衡的，所以查找的时间复杂度为 **O(log n)**。

### 三、红黑树的性能

红黑树保证在最坏情况下的操作时间复杂度为 **O(log n)**。由于红黑树的高度在任何情况下都不会超过 **2 * log n**，所以它能够确保在大多数操作中，时间复杂度是对数级别的。

* **查找操作**：最坏情况下，查找操作需要沿着树的高度遍历，时间复杂度为 **O(log n)**。
* **插入操作**：插入节点时，最坏情况下需要进行一次旋转和一些颜色修改，时间复杂度为 **O(log n)**。
* **删除操作**：删除节点时，最坏情况下需要进行多次旋转和颜色修改，时间复杂度为 **O(log n)**。

这些性能保证使得红黑树在需要频繁进行插入、删除、查找的动态数据集场景中，表现得非常高效。

### 四、STL中的红黑树实现

STL（Standard Template Library）是C++标准库的一部分，提供了许多常用的数据结构和算法。在STL中，`set`、`map`、`multiset` 和 `multimap` 这些容器的底层实现都是基于红黑树。

#### 1. **STL中的红黑树：`_Rb_tree`**

在STL的实现中，红黑树通常通过 `_Rb_tree` 类来表示。它是底层数据结构的核心，提供了用于存储元素的红黑树功能。每个关联容器（如 `set` 和 `map`）都使用 `_Rb_tree` 来实现插入、删除、查找等基本操作。

`_Rb_tree` 类通常具有以下成员：

```cpp
template <typename Key, typename T, typename Compare, typename Alloc>
class _Rb_tree {
    // 树的节点结构，包含颜色、父节点、左子节点、右子节点等信息
    struct _Rb_tree_node_base {
        _Rb_tree_color _M_color;          // 节点的颜色
        _Rb_tree_node_base* _M_parent;    // 父节点
        _Rb_tree_node_base* _M_left;      // 左子节点
        _Rb_tree_node_base* _M_right;     // 右子节点
    };
    
    // 节点内容定义：每个节点包含键值、左右子树指针等
    struct _Rb_tree_node : public _Rb_tree_node_base {
        Key _M_key;  // 存储键值
    };

    // 树的根节点
    _Rb_tree_node_base* _M_header;
    
    // 其他成员函数：插入、删除、查找、旋转等
};
```

#### 2. **`set` 和 `map` 使用 `_Rb_tree`**

在STL中，`set` 和 `map` 类是通过红黑树 `_Rb_tree` 来管理元素的。`set` 中只存储键，而 `map` 存储键值对（`std::pair<Key, Value>`）。以下是一个 `set` 的实现示例：

```cpp
template <typename Key, typename Compare = std::less<Key>, typename Alloc = std::allocator<Key>>
class set {
private:
    typedef _Rb_tree<Key, Key, _Identity<Key>, Compare, Alloc> _Rep_type;
    _Rep_type _M_t;  // 红黑树实例

public:
    set() = default;

    // 插入元素
    std::pair<typename _Rep_type::iterator, bool> insert(const Key& key) {
        return _M_t.insert_unique(key);
    }

    // 查找元素
    typename _Rep_type::iterator find(const Key& key) {
        return _M_t.find(key);
    }

    // 删除元素
    void erase(const Key& key) {
        _M_t.erase(key);
    }

    // 其他成员函数...
};
```

这里，`set` 类中 `_M_t` 就是 `_Rb_tree` 的实例，它提供了对元素的有序存储和高效的查找、插入、删除操作。通过 `insert_unique` 和 `find` 等方法，`set` 实现了对红黑树的封装，用户可以通过这些接口操作集合中的元素。

### 五、总结

红黑树是一种非常高效且平衡的二叉搜索树，它通过颜色和旋转操作维持树的平衡，保证最坏情况下的查找、插入和删除操作都具有 **O(log n)** 的时间复杂度。STL中的 `set`、`map` 等容器正是基于红黑树实现的，它们利用红黑树的平衡性，提供了高效的关联容器操作。深入理解红黑树的工作原理和在STL中的应用，有助于更好地掌握STL容器的实现与设计思想。
