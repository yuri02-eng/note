### **笔记：为什么需要虚拟 DOM (Virtual DOM)?**

#### **核心摘要**
虚拟 DOM 的本质是**用 JavaScript 对象来描述真实 DOM 结构**，是真实 DOM 的一层轻量级抽象。它的出现主要是为了解决**直接操作真实 DOM 带来的性能瓶颈和开发体验问题**，是现代前端框架（如 Vue、React）高性能渲染的核心机制。

---

#### **1. 解决的核心问题：真实 DOM 操作的性能瓶颈**

直接操作真实 DOM 的成本非常高，这主要体现在：

- **昂贵的属性**：真实 DOM 对象属性繁多，包含大量非渲染必需的属性（如事件绑定、自定义属性等），非常“重”。
- **触发重排与重绘**：每次直接对 DOM 的增删改操作都可能触发浏览器的**重排 (Reflow)** 和**重绘 (Repaint)**，这是最耗性能的过程。
- **性能损耗累积**：如果频繁进行 DOM 操作（例如循环更新列表），这种性能损耗会不断累积，导致应用卡顿，用户体验下降。

**没有虚拟DOM时（命令式操作）：**
开发者需要手动计算需要改变的最小部分，并直接使用 `document.createElement`、`appendChild`、`innerHTML` 等 API 进行精细操作，过程繁琐且极易出错或产生性能问题。

---

#### **2. 虚拟 DOM 的工作流程与优势**

虚拟 DOM 提供了一个**在 JS 内存中进行的“预操作”阶段**，完美规避了直接操作真实 DOM 的弊端。

**其工作流程可以概括为以下三步（Diff -> Patch）：**

1.  **生成虚拟节点 (VNode)**：
    - 当组件状态变化时，Vue 会依据模板或渲染函数，在内存中**重新生成一棵新的虚拟 DOM 树**。这是一个纯 JS 的操作，速度极快。

2.  **对比差异 (Diff Algorithm)**：
    - Vue 会将**新的虚拟 DOM 树**与**上一次渲染的旧虚拟 DOM 树**进行对比。
    - 通过高效的 **Diff 算法**，计算出两棵树之间的最小差异。这个算法会智能地比较节点类型、属性、子节点等，找出真正需要更新的节点。

3.  **批量更新 (Patch)**：
    - 计算出差异后，Vue 会将这些变更**批量地、一次性**地应用到真实的 DOM 上。
    - 这个过程叫做 **打补丁 (patching)**，`vue.runtime.js` 包含了这部分逻辑。

**这个过程带来的巨大优势：**

| 优势 | 解释 |
| :--- | :--- |
| **性能提升** | 将多次 DOM 操作**合并为一次**，极大地减少了直接操作 DOM 的次数，从而减少了重排和重绘，提升了渲染性能。 |
| **声明式编程与开发效率** | 开发者无需关心如何操作 DOM，只需**声明视图的状态**（`{{ data }}`）。Vue 的响应式系统会自动追踪依赖，并在数据变化时，通过虚拟 DOM 机制自动更新视图。这极大地解放了开发者，让开发者更专注于业务逻辑。 |
| **跨平台能力** | 虚拟 DOM 是 JS 对象，与浏览器平台无关。这使得 Vue 不仅可以渲染为 Web DOM，还可以通过不同的**渲染器 (Renderer)** 渲染到**原生应用**（Weex/NativeScript）、**Canvas**、甚至**命令行界面**等不同平台。 |

---

#### **3. 虚拟 DOM 在 Vue 中的体现**

- **与“声明式框架”的关系**：虚拟 DOM 是 Vue 实现**声明式 UI** 的底层基础。正是因为有了虚拟 DOM 的自动 Diff 和 Patch，开发者才能通过模板语法声明视图，而无需手动操作 DOM。
- **与“编译时/运行时”的关系**：
    - **编译时**：Vue 编译器将 `template` 编译为 `render` 函数，这个函数的作用就是**创建虚拟 DOM 节点**。
    - **运行时**：Vue 会执行 `render` 函数，得到虚拟 DOM 树，然后进行 Diff 和 Patch。

---

#### **总结：为什么需要虚拟 DOM？**

| 角度 | 原因 |
| :--- | :--- |
| **性能角度** | 通过**批量更新**和**最小化 DOM 操作**，解决了直接操作真实 DOM 的性能瓶颈，避免了不必要的重排和重绘。 |
| **开发角度** | 实现了**数据驱动视图**的声明式开发范式，让开发者从繁琐、易错的命令式 DOM 操作中解放出来，大幅提升开发效率和代码可维护性。 |
| **架构角度** | 提供了**跨平台渲染**的能力，为 Vue 的生态扩展（如小程序、原生应用开发）奠定了坚实的基础。 |

**简而言之，虚拟 DOM 是一种“以空间（内存中维护JS对象）换时间（减少DOM操作）”的策略，它是提升复杂应用性能、改善开发者体验的关键架构决策。**

### 一、虚拟DOM (Virtual DOM) 是如何生成的？

虚拟DOM的生成是Vue编译时和运行时协同工作的结果，其核心是 render 函数。

生成流程如下：

1.  模板编译 (编译时)：
    ◦ Vue应用中的 template 模板（如 <div>{{ message }}</div>）并不是直接送给浏览器执行的。

    ◦ Vue的编译器 (Compiler) 会将这些模板编译成 render 函数。这个步骤可以发生在构建时（例如使用Vite或Webpack），也可以发生在运行时（但不太推荐）。

2.  执行 Render 函数 (运行时)：
    ◦ 当组件的状态（如 message）发生变化时，Vue会执行这个 render 函数。

    ◦ render 函数内部会调用 createElement（通常简写为 h）函数，根据当前的状态数据，创建并返回一个用于描述当前组件视图的虚拟DOM树（一个JavaScript对象）。

3.  虚拟节点 (VNode) 对象：
    ◦ h 函数创建的每一个节点都是一个虚拟节点 (VNode)。它是一个轻量的JS对象，包含了渲染真实DOM所需的所有信息。

    ◦ 示例：一个简单的模板和其对应的VNode对象：
        <!-- 模板 -->
        <div id="app" class="container">
          <p>{{ message }}</p>
        </div>
        
        // 对应的 Render 函数可能返回的 VNode 对象结构
        {
          tag: 'div',
          props: { id: 'app', class: 'container' },
          children: [
            {
              tag: 'p',
              props: {},
              children: [ message ] // message 是一个变量或字符串
            }
          ]
        }
    

简单总结：模板 -> (编译成) -> Render函数 -> (执行后) -> 虚拟DOM树(VNode)。

### 二、虚拟DOM如何进行Diff？

当状态变化生成新的虚拟DOM树后，Vue需要知道具体哪些部分需要更新。这时，Diff算法就登场了。它的核心是：比较新旧两棵虚拟DOM树，找出差异，并只更新这些差异到真实DOM上。

Diff算法的核心策略与流程：

1.  同级比较，深度优先：
    ◦ 为了降低算法复杂度，Vue的Diff算法只会在同一层级（相同父节点的子节点）的VNode之间进行比较，而不会跨层级比较。如果发现节点已不存在，则会直接创建或删除节点。

2.  Key的关键作用：
    ◦ 在列表渲染 (v-for) 时，为每个节点提供一个唯一的 key 属性是至关重要的。

    ◦ key 是VNode的唯一标识。Diff算法通过 key 可以更高效地识别出哪些节点是相同的（可以复用），哪些是新增的或需要移动的。没有 key 会导致列表更新效率极低，甚至出现渲染错误。

3.  双端对比算法 (Vue 2/3的核心优化)：
    ◦ Vue的Diff算法不会粗暴地整体替换，而是采用了更智能的双端对比策略。它会同时遍历新旧子节点数组的两个端点（头头和尾尾、头尾和尾头），分情况处理，最大限度地复用已有的真实DOM节点，只进行属性更新或节点移动，而不是销毁和创建。

    ◦ 具体比较过程：

        ▪ 情况1：头头相同。对比新旧节点的头部，若相同则进行patch，指针后移。
        
        ▪ 情况2：尾尾相同。对比新旧节点的尾部，若相同则进行patch，指针前移。
        
        ▪ 情况3：旧头与新尾相同。说明节点被移动到了后面，将旧头节点移动到末尾，指针移动。
        
        ▪ 情况4：旧尾与新头相同。说明节点被移动到了前面，将旧尾节点移动到开头，指针移动。
        
        ▪ 如果以上情况都不符合，则会根据 key 映射来查找可复用的节点，若找到则移动，若找不到则新建。

4.   patch（打补丁）：
    ◦ 在Diff过程中，对于找到的相同节点（tag 和 key 都相同），Vue会调用 patchVnode 方法进行精细化比较，只更新发生变化的属性（如 class、style、事件监听器等）和文本内容。这个过程就是“打补丁”。

    ◦ 最终，所有计算出的变更会批量地、同步地应用到真实DOM上，完成视图更新。

Vue 3的优化：
Vue 3在Diff算法上做了进一步优化，引入了编译时静态标记。编译器可以分析出哪些节点是静态的，哪些是动态的，并为动态节点打上 patchFlag 标记。这样在运行时，Diff算法可以直接根据这些标记定位到需要比较的动态部分，完全跳过静态节点的对比，极大提升了Diff效率。

对比项 传统DOM操作 (无虚拟DOM) 虚拟DOM Diff机制

更新方式 手动计算并直接操作 自动计算最小差异，批量更新

性能 频繁操作，性能差 减少操作次数，性能优

开发方式 命令式，繁琐易错 声明式，专注数据逻辑

总结：
虚拟DOM通过 render 函数生成，是真实DOM的JS对象映射。Diff算法通过同级比较、key标识和双端对比等策略，智能地找出虚拟DOM树之间的最小差异，最后通过批量patch来高效更新视图。这套机制是Vue实现高性能声明式UI的基石。

### 那为什么需要虚拟dom来比较，而不直接用真实的DOM来比较差异？

可以，但直接比较真实DOM的效率极低，成本巨大，几乎不可行。 虚拟DOM的引入正是为了创造一个可以高效对比的“蓝图”，从而避免直接操作昂贵且低效的真实DOM。

下面我们从几个关键点来详细解释为什么不能直接用真实DOM来比较差异：

1. 真实DOM的“重量级”属性 (性能成本)

• 真实DOM对象非常“重”：浏览器中的真实DOM元素是一个包含大量属性、方法和事件处理程序的复杂对象。它不仅包含渲染所需的信息（如 id, class, innerHTML），还包含了许多与渲染无关的浏览器内部属性和方法（如事件处理器、自定义数据属性等）。

• 对比操作成本高昂：直接比较两个真实DOM树的差异，意味着需要遍历这两个极其复杂的对象结构，并逐个比较它们的属性。这个遍历和比较的过程本身就会消耗大量的计算资源（CPU），性能开销非常大。

而虚拟DOM是一个轻量的纯JavaScript对象，它只包含描述视图所必需的最少属性（如 tag, props, children）。对比两个JS对象的开销，比对比两个真实DOM节点的开销要小几个数量级。

2. 直接操作真实DOM的代价 (渲染成本)

这才是最核心的原因。即使你费了很大力气直接比较出了真实DOM的差异，后续的更新操作也会遇到瓶颈。

• 触发重排与重绘：对真实DOM的任何直接操作（如修改内容、添加/删除节点、改变样式）都会立即触发浏览器的重排 (Reflow) 和重绘 (Repaint)。这是浏览器工作流程中最耗性能的部分。

• 无法批量更新：如果没有虚拟DOM这层抽象，数据每次微小的变化都可能导致对真实DOM的多次直接操作。例如，一个循环更新10次数据，就会触发10次DOM更新和可能10次重排重绘，性能灾难随之而来。

虚拟DOM的Diff-Patch机制解决了这个问题：
1.  在内存中完成所有计算：所有的比较（Diff）都在JavaScript内存中进行，不会触及真实DOM，因此不会触发任何浏览器重排或重绘。
2.  批量更新：计算出所有差异后，虚拟DOM会将所有变更集中起来，一次性提交给真实DOM。浏览器只需要进行一次重排和重绘流程，就完成了所有视图更新，性能得到极大提升。

3. 开发与维护的复杂度 (工程成本)

• 命令式编程的困境：如果没有虚拟DOM提供的抽象层，开发者就需要自己编写命令式代码来精确描述如何更新DOM。例如：“如果列表A中某项数据变了，找到对应的那个<li>元素，然后修改它的第三个子节点的文本内容……”

• 代码繁琐易错：这种手动操作DOM的代码非常冗长、难以维护，并且极易出错。逻辑会分散在各个数据修改的地方，很容易产生状态和视图不一致的Bug。

虚拟DOM带来了声明式编程的便利：
开发者只需要关心数据的最终状态（“视图应该是什么样”），而“如何高效地更新视图”这个脏活累活完全交给虚拟DOM和Diff算法自动完成。这极大地提升了开发体验和代码的可维护性。
