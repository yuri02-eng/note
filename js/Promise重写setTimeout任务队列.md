### 背景

在传统的 JavaScript 异步编程中，我们经常使用 `setTimeout` 来实现延时任务，通常这样写：

```javascript
setTimeout(() => {
  console.log("任务 1 完成");
}, 1000);

setTimeout(() => {
  console.log("任务 2 完成");
}, 2000);

setTimeout(() => {
  console.log("任务 3 完成");
}, 1500);
```

这样写的缺点是：

1. **回调地狱**：每个 `setTimeout` 都是独立的，缺少顺序控制。如果我们想让这些任务按顺序执行，并且能处理每个任务完成后的操作，这样的代码就不太灵活了。
2. **顺序执行问题**：上述代码会导致任务异步执行，尽管我们期望任务按顺序完成，但并不能保证它们的顺序，因为任务的延迟时间不同。

使用 `Promise` 可以帮助我们更好地控制任务的执行顺序和错误处理，避免这些问题。

### 目标

我们要做的就是重写 `setTimeout` 的任务队列，用 `Promise` 来保证任务按顺序执行。我们要：

1. **按顺序执行**：任务按给定的顺序执行，不会并发。
2. **延迟执行**：每个任务都可以有不同的延迟时间。
3. **链式调用**：我们可以将任务添加到队列中，并且保证每个任务执行完后再执行下一个。

### 设计原理

1. **Promise 的链式调用**：

   * 在 `Promise` 中，每个 `.then()` 调用都会返回一个新的 `Promise`，这就允许我们将多个异步操作链接起来，形成一个链式执行的结构。
   * 每个 `Promise` 的执行会有一个“等待期”，直到 `resolve()` 或 `reject()` 被调用，才会继续往下执行。通过链式调用，我们能控制每个任务的执行顺序。

2. **队列中的异步控制**：

   * 我们用一个队列来管理任务，每当有新的任务加入时，都会通过 `Promise.then()` 将任务添加到队列中。
   * 当上一个任务完成时，才会开始执行下一个任务，这样就能确保任务的顺序性。

### 实现细节

```javascript
class TimeoutQueue {
    constructor() {
        // 初始化时，队列是一个已经解决的 Promise
        this.queue = Promise.resolve();
    }

    // 添加任务到队列
    addTask(fn, delay) {
        // 返回一个新的 Promise，它在指定的 delay 后执行 fn()
        this.queue = this.queue.then(() => {
            return new Promise((resolve) => {
                setTimeout(() => {
                    fn();   // 执行任务
                    resolve(); // 任务完成时 resolve
                }, delay);
            });
        });
    }

    // 执行任务队列
    run() {
        // 返回最终的 Promise，这样可以链式调用
        return this.queue;
    }
}

// 示例使用：
const queue = new TimeoutQueue();

// 添加任务，任务按顺序执行
queue.addTask(() => console.log("任务 1 执行"), 1000);  // 延时1秒
queue.addTask(() => console.log("任务 2 执行"), 2000);  // 延时2秒
queue.addTask(() => console.log("任务 3 执行"), 1500);  // 延时1.5秒

// 运行队列
queue.run().then(() => {
    console.log("所有任务执行完成");
});
```

### **如何工作**

1. **初始化队列**：

   * 在 `TimeoutQueue` 构造函数中，`this.queue` 被初始化为 `Promise.resolve()`，表示一个已经完成的 Promise。这样，任务队列一开始就处于“空”状态，并且不会阻塞接下来的任务添加。

2. **添加任务到队列**：

   * 当调用 `addTask(fn, delay)` 时，每个任务都被包裹在一个 `Promise` 中。
   * `this.queue.then(...)` 确保每个新任务的执行是在前一个任务完成后进行的，即任务是按顺序执行的。

3. **延迟执行**：

   * 每个任务通过 `setTimeout` 来延迟执行。延时的时间由 `delay` 参数控制。
   * `setTimeout` 的回调函数中，执行了传入的任务 `fn()`，并且在任务完成后通过 `resolve()` 通知 Promise 任务已经完成。

4. **链式调用**：

   * 每次调用 `addTask` 方法，都会返回一个新的 `Promise`，并且通过 `this.queue.then()` 链接到前一个 Promise。这种链式调用确保了任务的顺序执行。
   * `run()` 方法返回的是队列中所有任务的最终 Promise，表示所有任务都已经完成。

5. **执行队列**：

   * 当队列中的所有任务完成时，可以在 `run().then()` 中处理所有任务完成后的回调，比如输出 `"所有任务执行完成"`。

### **执行效果**

```bash
任务 1 执行
任务 2 执行
任务 3 执行
所有任务执行完成
```

即使任务的延迟时间不同（1秒、2秒、1.5秒），它们仍然按顺序执行，确保任务的顺序不被打乱。

### **扩展与改进**

1. **任务取消**：

   * 可以在 `TimeoutQueue` 中添加一个 `cancel()` 方法，用来取消当前队列中还未执行的任务。例如，添加一个取消标志，任务检查这个标志是否被设置。

2. **并发执行**：

   * 如果你希望任务可以并发执行（而不是一个接一个的顺序执行），可以修改 `addTask` 方法，不使用链式 `then()`，而是直接启动并发任务。这种情况需要考虑并发控制和错误处理。

3. **任务优先级**：

   * 可以引入任务优先级，将任务按优先级分配到队列中，并确保高优先级的任务先执行。

4. **错误处理**：

   * 如果任务发生错误，可以在 `then()` 中加入错误处理函数，或者在 `catch()` 中捕获异常，并执行相应的回调。

   ```javascript
   queue.addTask(() => {
       throw new Error("任务失败");
   }, 1000).catch(err => {
       console.log("任务出错：", err);
   });
   ```

### 总结

使用 `Promise` 来重写 `setTimeout` 任务队列，能够确保任务按顺序执行，同时保证了任务之间的异步关系。通过这种方式，我们实现了更为灵活且结构清晰的异步任务管理方式，比传统的 `setTimeout` 更易于扩展和维护。此外，`Promise` 提供了强大的错误处理和链式调用功能，可以帮助开发者有效地管理复杂的异步任务。
