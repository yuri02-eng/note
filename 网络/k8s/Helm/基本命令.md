# Helm 学习详细笔记

## 1. 介绍

### 1.1 什么是 Helm？

Helm 是 Kubernetes 的一个包管理工具，类似于 Linux 系统中的 `apt` 或 `yum`，它帮助你简化和自动化 Kubernetes 中应用的安装、配置、管理和升级。通过 Helm，你可以将 Kubernetes 资源封装成一个 Chart（类似于应用的包），通过简单的命令快速在 Kubernetes 集群中进行部署、管理、更新等操作。

### 1.2 Helm 的用途

Helm 能帮助开发者和运维人员减少手动部署的复杂度，特别是在处理微服务和应用的生命周期管理时，Helm 大大减少了重复工作，并且提供了易于管理和版本控制的方式。它能够：

* 简化 Kubernetes 资源的管理。
* 轻松共享和版本化 Kubernetes 应用。
* 自动处理应用的配置和依赖。
* 支持应用的安装、升级、回滚。

## 2. Helm 组件

### 2.1 Helm 客户端

Helm 客户端是命令行工具，用户通过 Helm 客户端来创建、安装、管理和删除 Helm Charts。它主要负责：

* 本地 Chart 开发。
* 从仓库下载 Chart。
* 向 Tiller 或 Kubernetes API 发出请求来管理应用。
* 查询 release 信息，执行升级或删除操作。

### 2.2 Tiller 服务端（仅适用于 Helm v2）

Tiller 是 Helm v2 的服务端组件，负责接收客户端的请求并执行。Tiller 会和 Kubernetes API 交互，管理应用的安装、升级、回滚等操作。Helm v3 中已经移除了 Tiller，改为直接与 Kubernetes API 交互。

### 2.3 Helm 3 的架构

Helm 3 移除了 Tiller，将客户端和 Kubernetes API 之间的所有操作通过 Helm 客户端直接实现，简化了安全性和管理。对于 Helm v3 用户，Tiller 已不再需要。

## 3. 安装 Helm

### 3.1 安装 Helm 客户端（Helm v3）

1. 使用以下命令下载安装 Helm 3：

   ```bash
   curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
   ```

2. 验证 Helm 安装：

   ```bash
   helm version
   ```

### 3.2 Helm v2 安装（需要 Tiller）

1. 使用以下命令安装 Helm v2（如果你的集群仍然使用 Tiller）：

   ```bash
   helm init
   ```

2. 确保 Tiller 已正确安装：

   ```bash
   kubectl get pods -n kube-system -l app=helm
   ```

## 4. Helm Charts

### 4.1 Chart 结构

Chart 是 Helm 的核心，包含 Kubernetes 应用的资源定义。Chart 的结构如下：

```
mychart/
├── charts/              # 存放子 Chart
├── Chart.yaml           # Chart 的元数据文件
├── values.yaml          # Chart 的默认配置
├── templates/           # 存放 Kubernetes 资源模板文件
│   ├── deployment.yaml
│   ├── service.yaml
│   └── ingress.yaml
└── README.md            # Chart 使用说明
```

### 4.2 `Chart.yaml`

`Chart.yaml` 是 Chart 的元数据文件，包含 Chart 的基本信息，例如名称、版本、描述等。

```yaml
apiVersion: v2
name: mychart
description: A Helm chart for Kubernetes
version: 0.1.0
appVersion: "1.0"
```

### 4.3 `values.yaml`

`values.yaml` 是 Chart 的配置文件，定义了应用的默认配置。用户可以通过 `--set` 或 `-f` 参数在安装时覆盖默认配置。

```yaml
replicaCount: 2
image:
  repository: nginx
  tag: latest
  pullPolicy: IfNotPresent
```

### 4.4 `templates/`

存放 Kubernetes 资源的模板文件，Helm 会渲染这些模板并提交到 Kubernetes 中。常见的模板文件包括：

* `deployment.yaml`：部署资源模板。
* `service.yaml`：服务资源模板。
* `ingress.yaml`：Ingress 资源模板。

### 4.5 安装 Chart

通过 Helm 可以轻松安装 Chart：

```bash
$ helm install my-release ./mychart
```

如果需要指定自定义的配置文件，可以使用 `-f` 参数：

```bash
$ helm install my-release ./mychart -f custom-values.yaml
```

## 5. Helm 常用命令

### 5.1 查看 Helm 版本

```bash
$ helm version
```

### 5.2 查看 Helm 仓库

```bash
$ helm repo list
```

### 5.3 安装 Chart

```bash
$ helm install my-release ./mychart
```

### 5.4 卸载 Chart

```bash
$ helm uninstall my-release
```

### 5.5 更新 Chart

```bash
$ helm upgrade my-release ./mychart
```

### 5.6 查看 Release 状态

```bash
$ helm status my-release
```

### 5.7 查看 Release 历史

```bash
$ helm history my-release
```

### 5.8 回滚 Release

```bash
$ helm rollback my-release 1
```

### 5.9 列出所有的 Releases

```bash
$ helm list
```

### 5.10 查找 Chart

```bash
$ helm search mysql
```

### 5.11 查看 Chart 详细信息

```bash
$ helm inspect stable/mysql
```

## 6. 使用 `--set` 和 `-f` 参数覆盖 `values.yaml`

### 6.1 使用 `--set` 覆盖

```bash
$ helm install my-release ./mychart --set replicaCount=3
```

### 6.2 使用 `-f` 参数覆盖配置文件

```bash
$ helm install my-release ./mychart -f custom-values.yaml
```

### 6.3 使用 `--set` 覆盖多层配置

```bash
$ helm install my-release ./mychart --set image.tag=v1.2.3
```

## 7. 高级用法

### 7.1 使用模板函数

Helm 使用 Go 模板引擎，支持多种内置模板函数，如 `quote`、`upper`、`lower` 等。

例如，将字符串转换为大写：

```yaml
k8s: {{ .Values.course.k8s | upper }}
```

### 7.2 使用管道（Pipeline）

通过管道将多个操作连接起来：

```yaml
k8s: {{ .Values.course.k8s | upper | quote }}
```

### 7.3 使用命名模板

命名模板用于定义可以复用的模板。在模板中使用 `define` 关键字定义一个模板，并通过 `template` 关键字引用。

```yaml
{{ define "mychart.labels" }}
  labels:
    from: helm
    date: {{ now | htmlDate }}
{{ end }}
```

### 7.4 使用 `include` 替代 `template`

`include` 函数与 `template` 类似，但可以控制输出的格式，特别适合处理空格问题。

```yaml
labels:
  {{- include "mychart.labels" . | indent 4 }}
```

### 7.5 使用 `default` 函数

`default` 函数用于设置默认值，如果某个值没有被提供，则使用默认值。

```yaml
myvalue: {{ .Values.hello | default "Hello World" | quote }}
```

### 7.6 Helm Hooks

Helm Hooks 是在特定生命周期事件（如安装前、安装后、升级前、升级后等）时运行的脚本。通过 hooks，用户可以在应用的生命周期内执行自定义操作。

常见的 hook 类型：

* `pre-install`
* `post-install`
* `pre-upgrade`
* `post-upgrade`

定义 hook 示例：

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: "install-job"
  annotations:
    "helm.sh/hook": pre-install
```

## 8. 打包和发布 Chart

### 8.1 打包 Chart

```bash
$ helm package ./mychart
```

这将生成 `.tgz` 文件。

### 8.2 上传 Chart 到仓库

```bash
$ helm push mychart-0.1.0.tgz [repo_name]
```

### 8.3 下载 Chart

```bash
$ helm pull [repo_name]/[chart_name]
```

## 9. Helm Chart 仓库

### 9.1 配置 Helm 仓库

你可以将 Helm 默认的仓库地址替换为自定义仓库，例如使用阿里云的镜像或 GitHub Pages：

```bash
$ helm repo add stable https://kubernetes-charts.storage.googleapis.com/
$ helm repo add custom https://github.com/helm/charts
```

### 9.2 使用 Helm 仓库更新

```bash
$ helm repo update
```

## 10. 总结

Helm 是一个强大的 Kubernetes 包管理工具，通过 Helm，开发者和运维人员可以轻松管理 Kubernetes 中的应用生命周期。通过模板系统、函数、管道等功能，Helm 可以让你方便地管理和定制应用的部署过程。掌握 Helm 的使用能显著提高你的工作效率，尤其是在复杂的 Kubernetes 环境中。

继续深入学习 Helm 将帮助你更好地管理 Kubernetes 集群中的应用，提高开发和运维的效率。
