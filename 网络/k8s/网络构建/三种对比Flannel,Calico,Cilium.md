### **Kubernetes CNI 插件选型笔记**

#### **一、 概述**

在 Kubernetes 中，Container Network Interface (CNI) 插件负责为 Pod 分配 IP 地址并管理节点间的网络通信。选择不同的 CNI 插件，即选择了不同的集群网络实现方案，它直接影响到网络的**性能、功能、安全性和运维复杂度**。

图片中所示的界面正是集群初始化时最关键的决策点之一，它代表了三种主流的网络方案路径。

---

#### **二、 核心选项详解**

##### **1. Flannel - 简单 Overlay 网络之选**

*   **核心模型**： **Overlay 网络**（如 VXLAN）。它在现有物理网络之上创建一个虚拟网络，简单可靠地实现 Pod 跨节点通信。
*   **工作原理**： 将原始 Pod 网络数据包封装在宿主机的 UDP 或 VXLAN 数据包中传输，到达目标节点后再解封装。
*   **优点**：
    *   **部署简单**： 配置极其简单，是快速搭建集群的首选。
    *   **兼容性好**： 对底层网络基本无特殊要求，能在绝大多数环境中运行。
*   **缺点**：
    *   **性能开销**： 网络封装和解封装会带来一定的性能损耗。
    *   **功能单一**： **不提供网络策略（Network Policy）**，无法实现 Pod 间的网络隔离。
*   **配置示例**：
    ```yaml
    # Flannel 的配置核心是指定 Pod 网段
    net-conf.json: |
      {
        "Network": "10.244.0.0/16", # Pod IP 地址范围
        "Backend": {
          "Type": "vxlan"           # 使用 VXLAN 后端
        }
      }
    ```
*   **适用场景**： **学习、测试、开发环境**，或对网络没有复杂要求的轻量级生产环境。

##### **2. Calico - 企业级 BGP 网络之选**

*   **核心模型**： **BGP（边界网关协议）**。它通过网络路由而非封装来实现 Pod 通信，性能更佳。也支持 IPIP 封装模式用于复杂网络。
*   **工作原理**： 每个节点上的 Calico 作为一个路由器，通过 BGP 协议向网络中的其他节点宣告本机 Pod 的路由信息。
*   **优点**：
    *   **高性能**： BGP 路由模式无封装开销，网络性能接近主机网络。
    *   **强大的网络策略**： 提供完整的 Kubernetes NetworkPolicy 支持，可实现精细的 Pod 级防火墙规则，是实现集群网络安全的基石。
*   **缺点**：
    *   **配置稍复杂**： 需要一定的网络知识，尤其在需要与物理网络设备（如路由器）对接 BGP 时。
*   **配置示例**：
    ```yaml
    # 一个 Calico 网络策略示例：禁止所有入口流量
    apiVersion: projectcalico.org/v3
    kind: NetworkPolicy
    metadata:
      name: default-deny-ingress
    spec:
      selector: all() # 选择所有 Pod
      types:
      - Ingress
      # 默认拒绝所有入口流量，再按需创建允许策略
    ```
*   **适用场景**： **大多数生产环境**，尤其是对性能和网络安全性（多租户隔离、微服务安全）有要求的场景。

##### **3. Cilium - 基于 eBPF 的下一代网络之选**

*   **核心模型**： **eBPF**。这是一种革命性的 Linux 内核技术，允许将程序注入内核执行，从而高效、安全地处理网络、安全性和可观测性任务。
*   **工作原理**： 使用 eBPF 程序替代传统的 iptables 和路由表来处理数据包，实现了内核级别的网络数据平面。
*   **优点**：
    *   **极致性能**： eBPF 提供了超高的网络性能和效率。
    *   **API 感知（L7）**： 不仅能基于 IP 和端口（L3/L4）做策略，还能识别 HTTP、gRPC 等应用层协议，实现如 `method: "GET" && path: "/api/*"` 的细粒度控制。
    *   **深度可观测性**： 提供强大的网络流量地图和监控能力。
*   **缺点**：
    *   **复杂度最高**： 概念较新，架构复杂，对运维人员技术要求高。
    *   **内核版本依赖**： 需要较新的 Linux 内核以支持全部功能。
*   **适用场景**： 对**性能、可观测性和安全有极致要求**的现代云原生环境，是**服务网格（Service Mesh）** 和未来技术架构的演进方向。

#### **三、 横向对比与选型指南**

| 特性 | **Flannel** | **Calico** | **Cilium** |
| :--- | :--- | :--- | :--- |
| **核心原理** | Overlay 封装 (VXLAN) | BGP 路由 / Underlay | **eBPF** (内核编程) |
| **安装配置** | ⭐⭐⭐⭐⭐ **(极简)** | ⭐⭐⭐ **(中等)** | ⭐⭐ **(复杂)** |
| **网络性能** | ⭐⭐⭐ **(有封装开销)** | ⭐⭐⭐⭐ **(高性能)** | ⭐⭐⭐⭐⭐ **(极致性能)** |
| **网络策略** | ❌ 不支持 | ✅ **L3/L4 策略 (强大)** | ✅ **L3/L4/L7 策略 (革命性)** |
| **可观测性** | ⭐⭐ **(基础)** | ⭐⭐⭐ **(中等)** | ⭐⭐⭐⭐⭐ **(深度应用层)** |
| **学习曲线** | **平缓** | 中等 | **陡峭** |



#### **四、 总结**

面对 Flannel, Calico, Cilium 这三个选项，您的选择实际上是确定集群网络的基调和未来发展路径。

*   **快速上手**：选 **Flannel**。
*   **生产就绪**：选 **Calico**，这是经过大量实践检验的、功能与稳定性俱佳的选择。
*   **面向未来**：如果团队技术实力雄厚且业务场景需要，勇敢选择 **Cilium**，它代表了云原生网络的未来。
