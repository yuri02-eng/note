## 11.1. Helm 的安装使用

### Helm 是什么？
Helm 就像是 Kubernetes 的"应用商店"，让你能够轻松地安装、升级和管理复杂的 Kubernetes 应用。

### 安装步骤
**在 Ubuntu 上安装：**
```bash
# 下载 Helm
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# 验证安装
helm version
```

**在 Windows 上安装：**
1. 使用 Chocolatey：`choco install kubernetes-helm`
2. 或者从 GitHub 下载 exe 文件

**在 Mac 上安装：**
```bash
brew install helm
```

### 验证安装
```bash
helm version
helm list  # 查看已安装的应用
```

## 11.2. Helm 的基本使用

### 核心概念理解
- **Chart**：就像是一个"软件安装包"，包含应用的所有配置
- **Release**：Chart 安装后的运行实例，就像安装好的软件
- **Repository**：存放 Chart 的仓库，就像手机应用商店

### 基本命令
```bash
# 搜索应用
helm search hub nginx  # 在官方仓库搜索
helm search repo nginx  # 在已添加的仓库搜索

# 添加仓库
helm repo add bitnami https://charts.bitnami.com/bitnami

# 安装应用
helm install my-nginx bitnami/nginx

# 查看已安装的应用
helm list

# 升级应用
helm upgrade my-nginx bitnami/nginx

# 卸载应用
helm uninstall my-nginx
```

### 实际例子：安装 WordPress
```bash
# 添加仓库
helm repo add bitnami https://charts.bitnami.com/bitnami

# 安装 WordPress
helm install my-wordpress bitnami/wordpress

# 查看状态
helm status my-wordpress
```

## 11.3. Helm 模板之内置函数和 Values

### 什么是模板？
模板就像是"填空题"，Helm 会用实际的值替换模板中的占位符。

### 内置函数举例
```yaml
# 字符串处理
{{ .Values.name | upper }}      # 转大写
{{ .Values.name | lower }}      # 转小写
{{ .Values.name | trunc 5 }}    # 截断前5个字符

# 默认值处理
{{ .Values.port | default 80 }} # 如果没设置端口，就用80

# 编码解码
{{ .Values.password | b64enc }} # Base64编码
```

### Values 文件理解
`values.yaml` 就像是应用的"设置文件"，里面定义了所有可配置的选项：

```yaml
# values.yaml - 就像游戏的设置界面
replicaCount: 3  # 要运行几个副本

image:
  repository: nginx  # 使用什么镜像
  tag: "1.19"        # 哪个版本
  pullPolicy: IfNotPresent

service:
  type: ClusterIP     # 服务类型
  port: 80           # 服务端口

resources:
  limits:
    memory: 512Mi    # 内存限制
    cpu: 500m        # CPU限制
```

### 模板中使用 Values
```yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-deployment
spec:
  replicas: {{ .Values.replicaCount }}  # 这里会被替换成3
  template:
    spec:
      containers:
      - name: nginx
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
        # 会被替换成 nginx:1.19
```

## 11.4. Helm 模板之模板函数与管道

### 管道操作理解
管道就像"流水线加工"，数据从左到右依次处理：

```yaml
# 简单理解：原料 → 加工1 → 加工2 → 成品
{{ .Values.name | upper | trunc 10 }}

# 分解步骤：
# 1. 取出 .Values.name（比如 "my-app"）
# 2. 转大写 → "MY-APP"  
# 3. 截断10字符 → "MY-APP"
```

### 常用函数组合
```yaml
# 安全地输出值
{{ .Values.password | b64enc | quote }}
# 步骤：密码 → Base64编码 → 加引号

# 生成配置文件
{{ .Values.config | toYaml | indent 4 }}
# 步骤：配置对象 → YAML格式 → 缩进4格
```

### 实际应用例子
```yaml
# 生成复杂的配置
data:
  application.yml: |
    {{ .Values.appConfig | toYaml | indent 4 }}
  
  database.yml: |
    {{ .Values.dbConfig | toJson | indent 4 }}
```

## 11.5. Helm 模板之控制流程

### 条件判断（if-else）
就像编程中的 if 语句，根据条件决定生成什么内容：

```yaml
{{ if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ .Release.Name }}-ingress
spec:
  rules:
  - host: {{ .Values.domain }}
{{ end }}

# 解释：只有当 ingress.enabled 为 true 时，才会生成 Ingress 配置
```

### 复杂条件判断
```yaml
{{ if and .Values.metrics.enabled (eq .Values.environment "production") }}
# 启用监控并且环境是生产环境时才生成监控配置
apiVersion: v1
kind: Service
metadata:
  name: {{ .Release.Name }}-metrics
{{ end }}
```

### 循环遍历（range）
就像 for 循环，用于处理列表数据：

```yaml
# 遍历环境变量
env:
{{ range $key, $value := .Values.envVars }}
  - name: {{ $key }}
    value: {{ $value | quote }}
{{ end }}

# 如果 Values.envVars 是：
# envVars:
#   DB_HOST: "localhost"
#   DB_PORT: "3306"
#
# 会生成：
# env:
#   - name: DB_HOST
#     value: "localhost"
#   - name: DB_PORT  
#     value: "3306"
```

### 遍历复杂结构
```yaml
# 遍历多个域名配置
{{ range .Values.ingress.hosts }}
- host: {{ .host }}
  http:
    paths:
    {{ range .paths }}
    - path: {{ .path }}
      backend:
        serviceName: {{ $.Release.Name }}
        servicePort: {{ $.Values.service.port }}
    {{ end }}
{{ end }}
```

## 11.6. Helm 模板之命名模板

### 什么是命名模板？
就像编程中的"函数"，把常用的代码块封装起来重复使用。

### 定义模板
在 `templates/_helpers.tpl` 中定义：

```yaml
{{/*
生成应用的标准标签
*/}}
{{- define "mychart.labels" -}}
app.kubernetes.io/name: {{ .Chart.Name }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/version: {{ .Chart.AppVersion }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end -}}

{{/*
生成完整的应用名称
*/}}
{{- define "mychart.fullname" -}}
{{- if .Values.fullnameOverride -}}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" -}}
{{- else -}}
{{- printf "%s-%s" .Release.Name .Chart.Name | trunc 63 | trimSuffix "-" -}}
{{- end -}}
{{- end -}}
```

### 使用模板
```yaml
# 在 deployment.yaml 中使用
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "mychart.fullname" . }}
  labels:
    {{- include "mychart.labels" . | nindent 4 }}
```

### 模板参数传递
```yaml
{{- define "mychart.image" -}}
{{- $registry := .registry -}}
{{- $repository := .repository -}}
{{- $tag := .tag -}}
{{- printf "%s/%s:%s" $registry $repository $tag -}}
{{- end -}}

# 使用：
image: {{ include "mychart.image" (dict "registry" .Values.registry "repository" .Values.image "tag" .Values.tag) }}
```

## 11.7. Helm 模板之其他注意事项

### 空格和缩进控制
Helm 模板中的 `-` 符号用于控制空格：

```yaml
# 正确控制缩进
labels:
  {{- include "mychart.labels" . | nindent 2 }}
  # nindent 2 表示嵌套缩进2空格

# 删除左边的空格
{{- if .Values.enabled }}  # 删除if前面的空格
content
{{- end }}                 # 删除end前面的空格
```

### 错误处理
```yaml
# 必需字段验证
{{ required "数据库地址是必需的" .Values.database.host }}

# 如果 database.host 没设置，安装时会报错并显示提示信息
```

### 范围（scope）理解
```yaml
# 注意 $ 符号访问外部变量
{{ range .Values.containers }}
- name: {{ .name }}           # 当前循环项的名称
  image: {{ .image }}          # 当前循环项的镜像
  port: {{ $.Values.service.port }}  # 使用 $ 访问外部的值
{{ end }}
```

## 11.8. Helm Hooks

### 什么是 Hooks？
Hooks 就像是"生命周期事件"，允许你在安装/升级的特定时间点执行操作。

### 常用的 Hook 类型
```yaml
# 安装前执行（用于准备数据库）
"helm.sh/hook": pre-install

# 安装后执行（用于发送通知）
"helm.sh/hook": post-install

# 删除前执行（用于清理数据）
"helm.sh/hook": pre-delete

# 升级前执行（用于数据库迁移）
"helm.sh/hook": pre-upgrade
```

### 实际应用例子
**数据库迁移 Job：**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: {{ .Release.Name }}-db-migration
  annotations:
    "helm.sh/hook": pre-upgrade    # 在升级前执行
    "helm.sh/hook-weight": "0"     # 执行顺序（数字小的先执行）
spec:
  template:
    spec:
      containers:
      - name: migrate
        image: myapp:migrate
        command: ["python", "manage.py", "migrate"]
      restartPolicy: Never
```

**安装后通知：**
```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: {{ .Release.Name }}-notification
  annotations:
    "helm.sh/hook": post-install    # 安装后执行
    "helm.sh/hook-weight": "5"      # 权重为5，会后执行
spec:
  template:
    spec:
      containers:
      - name: notify
        image: curlimages/curl
        command: 
        - curl
        - -X
        - POST
        - -d
        - "应用安装完成"
        - http://webhook.example.com/notify
```

### Hook 执行顺序控制
```yaml
# 通过 hook-weight 控制执行顺序
"helm.sh/hook-weight": "0"     # 最先执行
"helm.sh/hook-weight": "1"     # 其次执行  
"helm.sh/hook-weight": "5"     # 最后执行
```

## 实战练习：创建一个完整的 Chart

让我们创建一个简单的 Web 应用 Chart 来练习：

### 1. 创建 Chart 结构
```bash
helm create my-webapp
cd my-webapp
```

### 2. 修改 values.yaml
```yaml
replicaCount: 2

image:
  repository: nginx
  tag: "1.19"
  pullPolicy: IfNotPresent

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: true
  hosts:
    - host: myapp.example.com
      paths: 
        - path: /
          pathType: Prefix

resources:
  requests:
    memory: "128Mi"
    cpu: "100m"
  limits:
    memory: "256Mi" 
    cpu: "500m"
```

### 3. 测试安装
```bash
# 干运行测试
helm install my-app . --dry-run --debug

# 实际安装
helm install my-app .

# 查看状态
helm list
kubectl get pods
```
