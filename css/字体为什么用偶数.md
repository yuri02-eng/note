这是一个在网页设计领域经常被讨论的问题。简单来说，目前的**最佳实践是优先使用偶数字体大小**。

下面我将详细解释为什么，以及其中的历史演变和现状。

### 核心结论：优先使用偶数

对于绝大多数现代网页设计，建议使用**偶数字体大小**（如 14px, 16px, 18px, 20px, 24px）。这是目前行业的主流做法和共识。

---

1. 设计稿偶数，方便对不同media进行适应性计算，有时候要除以2
2. 字体丰满充实，以中字为例，12px可能左右5px,中间的一竖，就是2px,而11px的话中间只有1px,看起来不够丰满充实

### 为什么会有“奇数 vs 偶数”的讨论？

这个讨论主要源于早期低分辨率屏幕下的**字体抗锯齿（Anti-aliasing）和渲染问题**。

#### 1. 历史原因：旧屏幕与点阵字体
在非常早期的低分辨率 CRT 和 LCD 屏幕上（以及操作系统如 Windows XP），字体渲染引擎（如 ClearType）旨在通过次像素渲染来提高文本的清晰度。这种技术依赖于像素的物理布局（RGB条纹）。

*   **偶数字体大小**：在某些渲染引擎下，偶数字号（如 14px, 16px）更容易在像素网格上对称对齐，从而使字符形状更清晰、更锐利，避免出现模糊的“半像素”渲染。
*   **奇数字体大小**：奇数尺寸（如 13px, 15px）的中心线可能会落在两个物理像素之间，导致渲染引擎需要进行更多的抗锯齿处理，有时会使文字看起来略微模糊、发虚或颜色不正（特别是小字号时）。

因此，在过去，“使用偶数字号以获得更清晰的渲染”是一条非常重要的经验法则。

#### 2. 现代发展：高分辨率屏幕与变革
随着 **Retina（高清）屏幕**的普及，情况发生了根本性的变化。

*   **像素密度（PPI）极高**：现在的手机、平板和电脑屏幕像素密度非常高，单个像素已经难以用肉眼分辨。操作系统和浏览器不再使用次像素渲染，而是转向**灰度抗锯齿**或更先进的字体平滑技术。
*   **渲染单位变化**：在高清屏上，CSS 的 `1px` 不再对应一个物理设备像素，而是对应一个“逻辑像素”（或“参考像素”）。浏览器可以自由地使用多个物理像素来渲染一个逻辑像素，从而极大地平滑了边缘。
*   **矢量字体的优势**：我们如今使用的字体（如 WOFF2, TTF）都是矢量格式。无论字号是奇数还是偶数，浏览器都能将其缩放并渲染到像素网格上，清晰度的差异已经微乎其微，几乎不可感知。

### 现在的首要原则：一致性与可读性

在奇偶问题被技术发展基本解决后，更重要的排版原则是：

1.  **一致性（Consistency）**：在你的设计系统中建立一套有限的、成比例的字体大小尺度（如：12, 14, 16, 20, 24, 32...）。无论奇数偶数，**保持整个网站的字号 scale 有规律、成比例**远比纠结单个数字重要。这能建立视觉层次和秩序感。
2.  **可读性（Readability）**：正文文本通常建议在 `16px` 到 `20px` 之间（或 `1rem` - `1.25rem`），这是为了确保大多数用户无需缩放即可轻松阅读。这个范围基本都是偶数，因为它们是行业标准。
3.  **使用相对单位**：为了可访问性和响应式设计，强烈推荐使用相对单位 `rem` 或 `em` 而不是 `px`。
    *   `rem`：相对于根元素（`<html>`）的字体大小。
    *   `em`：相对于当前元素的字体大小。
    *   这样做的好处是，当用户调整浏览器默认字体大小时，你的页面布局可以更好地适配。

### 总结与建议

| 考量因素 | 建议 | 原因 |
| :--- | :--- | :--- |
| **历史渲染问题** | **优先选择偶数** | 在许多旧系统和低分辨率屏幕上，偶数的渲染可能更稳定。虽然现代屏幕差距很小，但遵循惯例无害。 |
| **现代实践** | **首选偶数** | 查看所有主流 CSS 框架（如 Bootstrap, Tailwind CSS）和设计系统（如 Google's Material Design），它们的默认字号尺度几乎全是偶数（12, 14, 16, 20, 24...）。这是事实上的标准。 |
| **特殊情况** | **不必过分纠结** | 如果你觉得 `15px` 或 `17px` 在你的设计中看起来**确实更好**，完全可以放心使用。在现代浏览器和高清屏上，其渲染效果没有问题。 |
| **核心原则** | **保持一致性和可读性** | 建立一套有限、和谐的字号尺度（例如以 `4px` 或 `6px` 为增量单位），并确保正文文本足够大（建议至少 `16px`）。 |

**最终建议：**
为了与行业标准保持一致，并避免任何潜在的旧设备渲染问题，**请优先使用偶数字体大小（如 14px, 16px, 18px, 20px）**。但请记住，最重要的是在整个项目中建立并遵守一套**系统性的、成比例的字号规范**。
