**Node（节点）**：你的物理机/虚拟机（有 192.168.241.137 这样的内网 IP）。

**Pod**：最小调度单位，里头包含 1~N 个容器，**共享一个 Pod IP**（10.244.x.y）。

**Service**：为一组 Pod 提供稳定的访问入口（ClusterIP）；**NodePort** 把它映射到节点端口对外可达。

**CNI/Flannel**：负责给每个节点分配一个 Pod 子网，并让不同节点上的 Pod 互通。



超好的问题！我分三块讲清楚：**Pod 为啥能共享一个 IP**、**Service 过来后到底进到 Pod 里的哪个容器**、以及**什么时候能直接访问 10.244.0.7**。

------

## 1) Pod 里多个容器是怎么“共享一个 IP”的？

靠 **Linux 网络命名空间（network namespace）**：

- 创建 Pod 时，kubelet 先起一个极小的 **“沙箱容器”（pause 容器）**，它只负责**提供网络命名空间**。
- Pod 里的所有业务容器都 **加入同一个网络命名空间**，因此共享：
  - 同一块虚拟网卡（连到 `cni0`/`flannel.1`），
  - **同一个 IP（例如 10.244.0.7）**，
  - 同一张路由表、`/etc/hosts`、`/etc/resolv.conf` 等网络视图。
- 结果就是：**容器与容器之间用 `localhost`/`127.0.0.1` 就能互相访问**（因为共享同一网络栈），端口也在一个空间里避免冲突（两个容器不能同时绑定 0.0.0.0:80）。

> 小结：Pod 不是“每容器一个 IP”，而是“**一组容器共享一个 Pod IP**”，这就是“sidecar 模式”能用 `localhost` 串起来的原因。

------

## 2) Service 命中了一个 Pod，流量落到 Pod 内部哪个容器？

- **Service 只知道“Pod IP + 端口”**，它**不会**直接选容器。
- Pod 内**哪个容器在那个端口监听**，流量就会被哪个容器的进程接住（因为共享同一网络栈）。
- 因此设计上通常：
  - 让“主业务容器”监听对外端口（例如 80），
  - 其他容器（sidecar，如日志/代理/适配器）监听其他端口或仅做本地转发。

> 如果两个容器抢同一个端口，会有 **“Address already in use”** 的端口冲突，Pod 会起不来。

------

## 3) 我能直接访问 `10.244.0.7` 吗？

看**你从哪里访问**：

- **从集群内（任意 Pod 或任意节点的主机上）**：可以。

  - 在你的这台主机（节点 `ubuntu`）上就能直接：

    ```bash
    curl http://10.244.0.7
    ```

  - 因为 Flannel 已给本机加了路由：`10.244.0.0/24` 走 `cni0`，本机上访问 Pod IP 会直达。

- **从集群里的“另一台节点”**：也可以。

  - Flannel 会在节点之间通过 VXLAN 封装把包送到目标节点，再从那台节点的 `cni0` 送达该 Pod。

- **从集群外的电脑（比如你的笔记本）**：默认 **不可以**，因为这是**集群专用的虚拟网段**，外部无路由。要想直接访问，有两条路：

  1. **给你的笔记本加静态路由**，把 `10.244.0.0/16` 指到某个节点（如 192.168.241.137）：

     - Windows（管理员 PowerShell）：

       ```powershell
       route add 10.244.0.0 mask 255.255.0.0 192.168.241.137
       ```

     - macOS / Linux：

       ```bash
       sudo route -n add 10.244.0.0/16 192.168.241.137
       # 或 sudo ip route add 10.244.0.0/16 via 192.168.241.137
       ```

     - 然后你的电脑就能直连 `10.244.0.7:80`。

       > 这要求中间网络允许转发；通常节点这边已经允许 `ip_forward`，防火墙没拦就行。

  2. 更常用、也更通用：**用 Service 的对外能力**

     - **NodePort / Ingress / LoadBalancer**。你已经用 **NodePort** 了：
        `http://192.168.241.137:<NodePort>`（例如 30275）是最佳实践。

> 实战建议：**开发/测试**用 `kubectl port-forward` 或 NodePort，**对外服务**用 Ingress（走 80/443 域名），**排障**时才临时直连 Pod IP。

## 给你几条“能看懂当下网络”的命令

```bash
# Pod 跑在谁上、有什么 IP
kubectl get pods -o wide

# 节点上 CNI 网桥和 flannel 接口
ip -br a | egrep 'cni0|flannel'

# 路由里 10.244.0.0/16 是怎么走的
ip route | egrep '10\.244|flannel|cni0'

# Service -> Endpoints（确认后端是哪些 Pod:Port）
kubectl get svc nginx
kubectl get endpoints nginx
```

------

### TL;DR

- **共享 IP 的原理**：所有容器加入 **同一个网络命名空间（pause 提供）**。
- **Service 到 Pod 后找谁处理？**：谁在该端口监听，谁就接（Service 不挑容器）。
- **能否直接访问 `10.244.0.7`？**
  - **节点内**/集群内：可以。
  - **集群外**：默认不行；要么加静态路由进 `10.244.0.0/16`，要么用 NodePort/Ingress 来访问。
