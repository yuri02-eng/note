# Vue 响应式系统与依赖收集核心原理笔记

## 一、核心思想：发布-订阅模式

Vue 的响应式系统基于经典的**发布-订阅模式** (Pub-Sub Pattern) 构建，其核心流程可以概括为：
1.  **收集依赖 (订阅)**：在组件渲染过程中，所有被使用的响应式数据属性都会记录下使用它们的代码（如：组件渲染函数、计算属性、侦听器）。
2.  **通知更新 (发布)**：当响应式数据的值发生变化时，通知所有之前记录了（订阅了）该数据的代码，让它们重新执行。

## 二、核心角色

为了实现这一流程，Vue 内部定义了三个关键角色：

| 角色 | 职责 | 类比 |
| :--- | :--- | :--- |
| **`Dep` (Dependency)** | 1. 一个响应式数据属性就对应一个 `Dep` 实例。<br>2. 用来收集所有依赖于该数据的**订阅者** (`Watcher` 或 `Effect`)。<br>3. 当数据变化时，负责通知所有订阅者。 | **发布者** / **主题** (Subject) |
| **`Watcher` / `Effect`** | 1. 代表一段**依赖于响应式数据的代码**（如：组件渲染函数、计算属性函数）。<br>2. 在自身执行前，会将自己设置为“当前活跃的订阅者”。<br>3. 执行时，会触发响应式数据的 `getter`，从而被收集到对应 `Dep` 中。<br>4. 收到 `Dep` 的通知后，会重新执行其管理的代码。 | **订阅者** (Subscriber) |
| **`Proxy` / `Object.defineProperty`** | 1. 拦截对响应式数据的**访问** (`get` 操作) 和**修改** (`set` 操作)。<br>2. 在 `get` 操作时，调用 `dep.depend()` 来收集当前活跃的订阅者。<br>3. 在 `set` 操作时，调用 `dep.notify()` 来通知所有订阅者更新。 | **拦截器** / **代理** |

## 三、依赖收集的详细流程

### Vue 2 (基于 `Object.defineProperty`)

```javascript
// 简化版原理实现
function defineReactive(obj, key, val) {
  const dep = new Dep(); // 每个属性都有自己的 Dep

  Object.defineProperty(obj, key, {
    enumerable: true,
    configurable: true,
    get: function reactiveGetter() {
      if (Dep.target) { // 如果当前有活跃的 Watcher
        dep.depend(); // 将这个 Watcher 收集到本属性的 dep 中
      }
      return val;
    },
    set: function reactiveSetter(newVal) {
      if (newVal === val) return;
      val = newVal;
      dep.notify(); // 数据变化，通知所有订阅的 Watcher 更新
    }
  });
}

// Dep 类
class Dep {
  static target = null; // 静态属性，指向当前正在计算的 Watcher
  subs = []; // 存储所有订阅者的数组

  depend() {
    if (Dep.target && !this.subs.includes(Dep.target)) {
      this.subs.push(Dep.target); // 收集 Watcher
    }
  }

  notify() {
    for (const sub of this.subs) {
      sub.update(); // 通知所有 Watcher 执行更新
    }
  }
}

// Watcher 类
class Watcher {
  constructor(getter) {
    this.getter = getter; // 这个 Watcher 所管理的函数（如：组件渲染函数）
    this.value = this.get();
  }

  get() {
    Dep.target = this; // 将自己设置为当前活跃的 Watcher
    const value = this.getter(); // 执行函数，触发函数内数据的 getter
    Dep.target = null; // 执行完毕，置空
    return value;
  }

  update() {
    this.get(); // 重新执行函数，重新计算值或重新渲染
  }
}
```

**流程描述：**
1.  组件初始化时，会为每个数据属性创建对应的 `Dep`。
2.  创建一个用于渲染组件的 `Watcher`，并执行 `watcher.get()`。
3.  在 `get()` 中，`Dep.target` 被设置为这个 `Watcher`。
4.  接着执行渲染函数，函数执行过程中，会读取模板中用到的数据，触发数据的 `getter`。
5.  在每个数据的 `getter` 中，会检查 `Dep.target` 是否存在。如果存在，就调用 `dep.depend()`，将当前 `Watcher` (`Dep.target`) 收集到该数据的 `Dep` 的 `subs` 数组中。
6.  渲染函数执行完毕，`Dep.target` 被置为 `null`。
7.  当数据被修改时，触发 `setter`，调用 `dep.notify()`。
8.  `notify()` 会遍历 `subs` 中所有的 `Watcher`，调用它们的 `update()` 方法，从而触发组件的重新渲染。

### Vue 3 (基于 `Proxy` + `Reflect`)

Vue 3 的实现更现代，核心思想不变，但角色名称和实现略有不同。

* **`ReactiveEffect`**：取代了 `Watcher` 的概念，代表一个副作用函数（如：渲染函数）。

*   **`targetMap`**：一个全局的 WeakMap，用于存储每个响应式对象与其对应的 `depsMap`。
    *   `key`: 原始对象
    *   `value`: `depsMap` (一个 Map)
    
*   **`depsMap`**：存储一个对象的所有属性与其对应的 `dep`。
    *   `key`: 属性名
    *   `value`: `dep` (一个 Set，存储所有 `ReactiveEffect`)
    
* **`activeEffect`**：全局变量，取代 `Dep.target`，指向当前正在运行的 `ReactiveEffect`。

  好的，我们来详细拆解 Vue 3 响应式系统中 `targetMap`、`depsMap`和 `dep`（Set）这三个核心数据结构的作用以及它们之间的关系，看看它们究竟记录了“什么”和“什么”之间的联系。

  ## 核心目标：建立“数据属性”与“依赖它的副作用函数”之间的映射关系

  Vue 3 响应式系统的核心目标就是自动追踪**哪些数据属性被哪些副作用函数（如组件渲染函数、计算属性、`watchEffect`）所依赖**。当数据属性发生变化时，系统需要**精确地知道需要重新运行哪些副作用函数**。这三个数据结构就是为了高效地存储和管理这种依赖关系而设计的。

  ## 三层结构：从对象到属性到依赖

  这种关系是通过一个**三层嵌套**的数据结构来组织的：

  1. **`targetMap`(WeakMap)**
     - **Key 是什么？** 原始对象（`target`）。就是你传递给 `reactive()`、`ref()`（对于对象值）或 `shallowReactive()`的那个原始 JavaScript 对象。
     - **Value 是什么？** 一个 `depsMap`(Map)。
     - **它记录了什么？** `targetMap`记录了 **哪个原始对象** 关联着 **它所有属性的依赖关系集合 (`depsMap`)**。
     - **为什么用 WeakMap？**
       - **弱引用键 (Weak Key)：** `targetMap`的键（原始对象）是弱引用。这意味着当原始对象本身不再被其他地方引用（可以被垃圾回收）时，它在 `targetMap`中的整个条目（包括对应的 `depsMap`和 `dep`Set）也会被自动清除。这**避免了内存泄漏**，因为响应式系统不会阻止原始对象被回收。
       - **目的：** 将**原始对象**映射到它**所有属性的依赖关系总览 (`depsMap`)**。
  2. **`depsMap`(Map)**
     - **Key 是什么？** 对象的属性名（`key`）。例如 `'count'`、`'name'`、`'items'`。
     - **Value 是什么？** 一个 `dep`(Set of `ReactiveEffect`)。
     - **它记录了什么？** `depsMap`记录了 **原始对象的哪个具体属性** 关联着 **所有依赖于这个属性的副作用函数集合 (`dep`Set)**。
     - **为什么用 Map？** Map 允许使用字符串（属性名）作为键，方便查找特定属性的依赖集合。
     - **目的：** 将**对象的特定属性**映射到**所有依赖于该属性的副作用函数集合 (`dep`Set)**。
  3. **`dep`(Set of `ReactiveEffect`)**
     - **存储什么？** 存储的是 `ReactiveEffect`实例。
     - **`ReactiveEffect`是什么？** `ReactiveEffect`是 Vue 3 中代表一个**副作用函数**的类。它可以是一个：
       - 组件的渲染函数
       - `computed`属性的计算函数
       - `watchEffect`的回调函数
       - `watch`的 getter 函数
     - **它记录了什么？** `dep`Set 记录了 **所有依赖于某个对象某个具体属性的副作用函数 (`ReactiveEffect`)**。
     - **为什么用 Set？** Set 保证存储的 `ReactiveEffect`实例是唯一的，避免重复添加同一个依赖。当属性值变化时，遍历 Set 可以高效地通知所有依赖它的副作用函数重新执行。
     - **目的：** 存储**所有依赖于某个特定属性的具体副作用函数**。

  ## 关系总结图

  ```
  (WeakMap)
  targetMap: {
     原始对象A (key) ---------> depsMapA (value: Map)
     原始对象B (key) ---------> depsMapB (value: Map)
     ...
  }
  
            (Map)
  depsMapA: {
     属性名 'count' (key) ---------> dep_count (value: Set of ReactiveEffect)
     属性名 'name'  (key) ---------> dep_name  (value: Set of ReactiveEffect)
     ...
  }
  
            (Set)
  dep_count: [
     ReactiveEffect1 (e.g., 组件渲染函数),
     ReactiveEffect2 (e.g., 一个计算属性),
     ReactiveEffect3 (e.g., 一个 watchEffect),
     ...
  ]
  ```

  ## 流程示例：依赖收集与触发更新

  假设我们有一个响应式对象 `state = reactive({ count: 0 })`，并且有一个组件在其渲染函数中使用了 `state.count`。

  1. **创建响应式对象：**
     - `state = reactive({ count: 0 })`创建一个 `Proxy`代理对象。
     - 在 `targetMap`中为原始对象 `{ count: 0 }`创建一个新的 `depsMap`条目（如果不存在的话）。
  2. **组件渲染（依赖收集）：**
     - 组件首次渲染时，会创建一个 `ReactiveEffect`包裹其渲染函数（假设叫 `renderEffect`）。
     - 执行 `renderEffect.run()`：
       - 将全局 `activeEffect`设置为 `renderEffect`。
       - 执行渲染函数。
       - 渲染函数访问 `state.count`，触发 `Proxy`的 `get`拦截器。
       - 在 `get`拦截器中调用 `track(target, key)`：
         - `target`是原始对象 `{ count: 0 }`。
         - `key`是 `'count'`。
         - `track`函数：
           - 从 `targetMap`中找到 `{ count: 0 }`对应的 `depsMap`（我们叫它 `depsMap_state`）。
           - 在 `depsMap_state`中找到 `'count'`对应的 `dep`Set（我们叫它 `dep_count`）。如果不存在，则创建一个新的空 Set 并放入 `depsMap_state`。
           - 将当前活跃的 `activeEffect`（即 `renderEffect`）添加到 `dep_count`Set 中。
       - `state.count`的值被返回。
     - 渲染函数执行完毕，`activeEffect`被置为 `null`。
  3. **修改数据（触发更新）：**
     - 执行 `state.count++`，触发 `Proxy`的 `set`拦截器。
     - 在 `set`拦截器中调用 `trigger(target, key)`：
       - `target`是原始对象 `{ count: 0 }`。
       - `key`是 `'count'`。
       - `trigger`函数：
         - 从 `targetMap`中找到 `{ count: 0 }`对应的 `depsMap_state`。
         - 从 `depsMap_state`中找到 `'count'`对应的 `dep_count`Set。
         - 遍历 `dep_count`Set 中的所有 `ReactiveEffect`（这里只有 `renderEffect`）。
         - 调用每个 `ReactiveEffect`的 `run()`或 `schedule()`方法。
     - `renderEffect`被调度执行，组件重新渲染。

  ## 总结：各 Map/Set 记录了什么

  相当于说记录了，key是这个对象，然后value是一个map(这个map的key是这个对象中的key，value是使用了这个对象的这个数据的所以地方的函数)在这个对象的这个属性修改时，执行回调触发页面更新。

  - **`targetMap`(WeakMap):**
    - **记录：** **原始对象** -> **该对象所有属性的依赖关系总览 (`depsMap`)**。
    - **目的：** 按对象组织依赖，利用 WeakMap 特性防止内存泄漏。
  - **`depsMap`(Map):**
    - **记录：** **对象的某个属性名** -> **所有依赖于该属性的副作用函数集合 (`dep`Set)**。
    - **目的：** 按属性组织依赖，实现属性级别的依赖追踪。
  - **`dep`(Set of `ReactiveEffect`):**
    - **记录：** **所有依赖于某个特定属性的具体副作用函数 (`ReactiveEffect`)**。
    - **目的：** 存储需要在该属性变化时被通知并重新执行的函数列表。

  通过这三层结构，Vue 3 能够高效、精确地管理响应式数据与副作用函数之间的依赖关系，确保数据变化时只触发必要的更新，这是其高性能响应式系统的基石。

  **流程描述：**

1.  调用 `reactive()` 创建响应式对象，其代理拦截了 `get` 和 `set`。
2.  调用 `watchEffect(fn)` 创建一个 `ReactiveEffect` 并执行 `run()`。
3.  在 `run()` 中，`activeEffect` 被设置为这个 `effect`。
4.  接着执行函数 `fn`，函数执行过程中，会读取响应式数据，触发 `get` 操作。
5.  在 `get` 操作中，调用 `track(target, key)`。`track` 函数会从 `targetMap` 中找到对应属性的 `dep`（一个 Set），并将当前 `activeEffect` 添加进去。
6.  函数 `fn` 执行完毕，`activeEffect` 被置为 `null`。
7.  当数据被修改时，触发 `set` 操作，调用 `trigger(target, key)`。
8.  `trigger` 函数会从 `targetMap` 中找到对应属性的 `dep`，然后遍历并执行其中所有 `effect` 的 `run()` 方法。

## 四、不同API的依赖收集时机

| API | 依赖收集时机 | 说明 |
| :--- | :--- | :--- |
| **模板 (Template)** | 组件首次渲染和重新渲染时 | 模板中使用的所有响应式变量都会被自动收集。 |
| **`computed`** | 计算属性首次计算或被访问时 | 计算属性的 getter 函数中使用的响应式变量会被收集。计算属性本身也是一个 `ReactiveEffect`。 |
| **`watch` / `watchEffect`** | 侦听器创建时 (`watchEffect`) 或依赖变化时 (`watch` 的 getter) | `watchEffect` 会立即执行并收集所有用到的依赖。`watch` 会执行其源函数或 getter 来收集依赖。 |
| **`setup()` 中的普通函数** | 不会自动收集 | 除非被模板、计算属性或侦听器使用，否则普通函数中的响应式变量不会被追踪。 |

## 五、最佳实践与注意事项

1.  **响应式数据必须用于“依赖收集”的上下文中**：只有在组件渲染、计算属性函数、侦听器函数等上下文中使用的响应式数据才会被收集。在普通的函数或 `setTimeout` 中直接使用，不会建立响应联系。

2.  **避免在运行时动态添加新属性** (Vue 2 局限性)：
    *   **Vue 2**：使用 `this.$set(object, key, value)` 或 `Vue.set()` 确保新属性是响应式的。
    *   **Vue 3**：`Proxy` 天然支持动态添加属性，直接赋值即可。

3.  **数组的处理**：
    *   **Vue 2**：通过重写数组的 `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse` 方法来触发更新。直接通过索引修改项 (`arr[index] = newValue`) 或修改长度不会被捕获，需使用 `Vue.set` 或数组的变异方法。
    *   **Vue 3**：`Proxy` 直接支持各种数组操作。

4.  **理解依赖更新是异步的**：数据变化后，Vue 会将组件更新推入一个队列，并在下一个事件循环中执行，以避免不必要的重复渲染。使用 `nextTick()` 来等待 DOM 更新完成。

5.  **计算属性基于它们的响应式依赖进行缓存**：只有当计算属性依赖的响应式数据发生变化时，它才会重新计算，否则返回缓存值。

## 总结

Vue 的依赖收集是一个精巧的自动化过程：
*   **核心**：`getter` 中收集（`track`），`setter` 中通知（`trigger`）。
*   **目标**：建立响应式数据与需要更新的副作用（组件、计算属性等）之间的映射关系。
*   **结果**：实现了数据驱动视图，开发者只需关心数据状态，DOM 更新由 Vue 自动高效地完成。

理解这一机制，有助于你编写更高效的 Vue 代码，并能够更好地调试与响应性相关的问题。
